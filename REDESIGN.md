# REDESIGN v3 — Portfolio Reframe

> Generated by `frontend-design-ui-ux` skill. Spec only — implementation delegated to engineering agent.
> Binds to `.ulpi/design/DESIGN.md` for locked tokens (palette, type, scales). This document overrides
> the tone, removes the Capability Ledger signature, and introduces new components.

---

## Design Read

**The feeling:** Quiet, confident, professional. A senior backend developer who does not need to prove
his worth with numbers or justify his choices with resource limitations. The page breathes. No
self-deprecation, no underdog narrative.

**The bet:** Trust through clarity and restraint, not through evidence/metrics. Remove the "look what I
did with almost nothing" posture entirely. Replace it with "this is what I do" — simple, direct, no
apology.

---

## Aesthetic Direction

**Committed direction:** editorial / refined corporate (carried forward from v2, minus the
"evidence-led" framing).

**Counterfactual test:** This look is NOT the generic answer for "backend dev portfolio" — no terminal
chrome, no cyber aesthetic, no "3 equal cards" layout, no stats dashboard. It reads as a calm
professional site, not a template.

**What changed from v2:**
- Removed the "Capability Ledger" signature (the proof strip with metrics was read as pretentious)
- Removed stats columns, numerical displays, and metric references
- Rewrote copy to eliminate underdog/self-deprecating tone ("a mi edad", "free tier", "open source" as
  narrative of struggle, "presupuesto limitado")
- Replaced cards with text blocks where possible
- Reduced decorative elements (borders, icons, accent bars)
- Simplified animations (less stagger, no clip reveals)

## Design Language (delta from DESIGN.md)

The existing `.ulpi/design/DESIGN.md` tokens for palette, type, spacing, radius, and motion are locked
and carried forward. This section only documents what changes.

### Signature (REPLACED)

**Old:** Capability Ledger — full-width proof strip with metrics (1 GB RAM, 99.9%, $0/mo).
**New:** Services blocks — three text-only sections describing what the developer does, without metrics.

The new signature is the **breathing space** itself — the confidence to say what you do without
backing it up with numbers. The one memorable element is the absence of the thing everyone else leads
with (self-promotion).

### Voice (REWRITTEN)

| Aspect | Old | New |
|--------|-----|-----|
| Register | Evidence-led, slightly defensive | Plain, confident, first person |
| Tone | "Mira lo que logre con casi nada" | "Esto es lo que hago" |
| Self-reference | "A mi edad", "autodidacta", "presupuesto limitado" | Removed entirely |
| Technical references | Free tier, 1GB RAM, 500MB memory, ARM64 | Removed from copy; kept in tech badges |

### Banned elements (specific to this redesign)

- Numerical proof points in copy (99.9%, 1GB, $0, 500MB, 3+ systems)
- Cards used for non-interactive content (approach blocks, services)
- Self-deprecating biography ("a mi edad decidi reinventarme")
- Buzzword technical lists (circuit breakers, rate limiting, health checks as decorative copy)

### Layout families

1. **Hero** — left-aligned name + title + tagline + capabilities line + CTAs. No right column. No stats.
2. **Services** — text blocks without cards, without icons, without borders. Just heading + paragraph.
3. **Approach** — text blocks without cards, without icons. Clean vertical spacing.
4. **Tech badges** — grid of chip-style badges (icon + name). No ruled list.
5. **Projects** — asymmetric grid (wide + narrow cards). Each card includes an animated architecture diagram.
6. **Contact** — toggle-expandable EmailJS form with validation and cooldown.

### 5. ArchDiagram (NEW — component inside ProjectCard)

**Purpose:** Animated architecture diagram showing the flow of a project. Pure CSS/HTML/Vue — no
external libraries, no canvas, no SVG complexity.

**Layout:** Responsive diagram with:
- Nodes: rounded boxes (radius 8px, surface bg, border, padding 12px 16px) with icon + label
- Edges: horizontal/vertical lines connecting nodes using CSS pseudo-elements (`::before`/`::after`)
- Flow animation: a small dot (6px circle, accent color) that moves along each edge using CSS
  `@keyframes` with staggered `animation-delay`
- Labels on edges: method/short description (mono, 10px, muted)

**Simple topology (2-3 nodes max per project for readability):**
```
[Client] ──HTTP──> [API Gateway] ──Route──> [Service] ──JPA──> [DB]
                                                         └──Pub/Sub──> [Cache]
```

**Props:**
```js
{
  nodes: [
    { id: 'client', label: 'Client', icon: 'mdi-account' },
    { id: 'gateway', label: 'Gateway', icon: 'mdi-router' },
    { id: 'service', label: 'Service', icon: 'mdi-cog' },
    { id: 'db', label: 'PostgreSQL', icon: 'mdi-database' },
  ],
  edges: [
    { from: 'client', to: 'gateway', label: 'HTTP' },
    { from: 'gateway', to: 'service', label: 'Route' },
    { from: 'service', to: 'db', label: 'JPA' },
  ]
}
```

**States:**
| State | Visual |
|-------|--------|
| Default | Diagram visible, animation playing in loop |
| Hover on node | Slight lift, border accent |
| Reduced motion | Animation disabled, static diagram with arrows |

**Accessibility:** `aria-label="Architecture diagram: Client connects to Gateway, Gateway routes to
Service, Service persists to PostgreSQL"` on the diagram container. Animation purely decorative.

**Implementation notes:**
- Use CSS Grid for node positioning (no absolute positioning needed)
- Lines between nodes using `::before` pseudo-elements with borders
- Flowing dot using `@keyframes moveDot`
- Animation cycles pause on `prefers-reduced-motion: reduce`

### 6. ContactSection (REWRITTEN — EmailJS form recovery)

**Purpose:** Allow visitors to send a message via EmailJS. Toggle-expandable form.

**Layout:** Card with accent left border. Toggle button (centered) expands form below. Form fields:
name (col-12 col-md-6), email (col-12 col-md-6), message (col-12), honeypot (hidden), submit button.

**Composable: `useContactForm.js`:**
```js
{
  form: { name, email, message, honeypot },
  sending: ref(false),
  contactExpanded: ref(false),
  cooldownUntil: ref(0),
  toggleContact, sendContact, scrollToContact
}
```

**States:**
| State | Visual | Behavior |
|-------|--------|----------|
| Collapsed | Toggle button visible | Click to expand |
| Expanded | Form visible, fields + submit | Fill and submit |
| Sending | Submit button loading spinner | Form disabled |
| Success | Quasar notify green + form reset | Cooldown 60s |
| Error | Quasar notify red | Form stays, can retry |
| Validation | Inline field errors | Focus first error |
| Cooldown | Notify warning | Ignore submit until cooldown expires |
| Honeypot triggered | Silent reject | Form submits but nothing happens |

**Validation:**
- Name: required
- Email: required + regex `/.+@.+..+/`
- Message: required
- Honeypot: must be empty

**Accessibility:**
- Form fields have `<label>` elements (via Quasar `q-input` `:label`)
- Toggle button has `aria-expanded` binding
- Error messages use `role="alert"`
- Honeypot has `tabindex="-1"` and `aria-hidden="true"`

## Accessibility Requirements

All components carry forward the a11y baseline from v2:
- `:focus-visible` outline on all interactive elements
- `prefers-reduced-motion: reduce` disables all animations
- Skip link at top of page
- `aria-label` on icon-only buttons
- `aria-hidden` on decorative elements
- Dynamic `lang` attribute update on language switch
- Color contrast: `--muted: #4a6a7a` on `--bg: #f2efe9` = 4.78:1 (AA)
- `--border: #8a7e72` on `--bg: #f2efe9` = 3.31:1 (AA for non-text)

New a11y for this redesign:
- ArchDiagram: `aria-label` describing the full flow
- Contact form: `aria-expanded` on toggle, `role="alert"` on errors
- BadgeStack: `aria-label` per badge
